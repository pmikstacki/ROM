# ROM research and prototype results — 2026-10-03

The fixed premise remains one Resource domain with authorized actions and atomic
committed changes/events. Backend optimization changes execution cost, not domain
meaning. Studio and aggregation/reporting remain outside this work cycle.

| Track | Evidence | Conclusion |
| --- | --- | --- |
| Query authoring and three physical paths | Eight conformance tests, 3,888 independent query/anchor vectors, repeated build/construction/read/write samples | Hybrid typed authoring is close to generated construction cost. | Strategy selector and planner adapters | Seven selector tests, 168 independent query comparisons, 594 timed observations | Small selection can avoid a bad path, but planning/admission overhead matters for short queries. | Explicit compensation | Forty cases in three integration tests, both stores, two real SQLite process exits | Targeted actions preserve unrelated changes. Unknown outcomes hold for reconciliation. | WASM | Nine engine tests, negative memory-limit control, repeated release observations | A bounded no-import guest is feasible; native host work is not covered by guest fuel. Actual ROM guest integration remains a later experiment. [Report](wasm-extension-research.md) |
| Skills authoring | Executable two-Resource template, three SQLite tests and a field-grant negative control | Ground a versioned skills catalog in tested public API examples. No human/agent usability evaluation or installed skills library is claimed. [Report](rom-skills-library-research.md) |

## Defects and rejected shortcuts

- Old snapshot compensation overwrites concurrent business data even when it uses
  a valid current revision. Prefer token-specific domain actions.
- Prototype SQL LIMIT before authorization loses visible rows. Keep policy before
  final result truncation.
- REAL coercion merges distinct large u64 values. JSON extraction alone conflates missing/null.
  Exact representations are mandatory.
- An early selector let cost/statistics choose between success and capacity error.
  Common actual collection admission now precedes strategy selection.
- Partial EXPLAIN prefix recognition accepted unknown plan nodes/index names.
  The prototype now uses a strict version-pinned whitelist and exact execution SQL.
- A zero-limit prototype query disagreed with its evaluator. The focused
  reproduction and corrected behavior are recorded in the independent review.

## Next measured steps

1. Test selector plan reuse and cost estimates on skewed, independently chosen workloads.
   Include mutation invalidation, memory, and allocation accounting.
2. Promote indexed execution only with actual ROM commit/index maintenance,
   migration/rebuild and recovery conformance. Current synthetic-journal evidence
   cannot substitute for that integration.
3. Before you create a public stateful plugin interface, exercise an authorized WASM proposal through actual ROM on both stores.
   Evaluate WIT/components separately.
4. Evaluate skills with real agent tasks and, when available, human authors. The
   executable templates validate API behavior, not usability by themselves.
5. Use a complete reference application and its upgrade/recovery journey to judge
   framework readiness. Multiwriter, shared tenancy and online migration are
   optional deployment profiles requiring explicit scope decisions.

These are next experiments, not additional completed capabilities. Optimizer
adoption remains guided by [implementation cost versus benefit](optimizer-adoption-cost.md),
with [scientific grounding](query-execution-scientific-basis.md) and explicit limits.
