## Minor: qualify callback execution bounds

The frozen guide, docs/operator-recovery.md:123, says:

> ROM bounds its execution, then checks current operator, service and Resource authority again before committing a result.

This can imply a finite wall-time bound for arbitrary trusted Rust callbacks.
`channels::supervision::run` applies a Tokio timeout, aborts the task, and awaits its completion.
Tokio cannot preempt blocking or non-yielding callback code.
Joining such code can retain the existing supervised work permit beyond the requested timeout.

State that host verifier callbacks must use cooperative async work and bounded I/O.
Describe the timeout and abort/join behavior without promising preemption of arbitrary native code.
Keep the existing guarantee that callbacks run outside the core commit gate and native transactions.
This is a documentation correction; the review does not request a new execution mechanism.
