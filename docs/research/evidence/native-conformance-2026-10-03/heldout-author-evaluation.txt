# Independent extracted-skill evaluation

**Spec: accepted. Quality: accepted. No blocking findings.** All four relocated workflows passed preflight and their selected examples. Each also passed a concrete author task that differs from the pre-skill baseline. This report supports the bounded Linux/full-source-checkout v1 workflow claim.

The evaluator did not implement the conformance library or the skills. However, the evaluator implemented earlier native compatibility work, reviewed this library, and completed the baseline. This is independent of the current implementations. It is not blind evaluation, human usability evidence, or proof of a causal productivity gain. The baseline passed too.

The bundle was assembled after the manifest-fidelity amendment. It was archived, extracted, and used outside the production checkout. Only the extracted SKILL.md files, shared README, canonical guide, and tools were used as skill instructions. No source skill files were needed. The assembler and source checkout remain explicit prerequisites; this is not a packaged-crate-only workflow.

Sanitized copies are retained here. No credentials, private fixture authorization file, publication, or source product edits are included.

## Attempts and limits

The Resource adaptation deliberately began with the copied uppercase rule. Its new lowercase test failed with actual 'HELP-9' versus required 'help-9'. The author changed the private codec to lowercase and obtained GREEN. [The RED log](evidence/rom-skills-heldout-resource-red.log) is a business-rule authoring result, not a framework or skill defect.

One initial artifact-generation attempt used python3, which was unavailable on the host. No files changed in that attempt. The author used the available Node tool instead. This is a local author-tool correction, not a missing ROM API or invented product failure. No compile or assertion failure was assigned to the skills.

The native checks prove the shared baseline contracts and the targeted negative, not crash recovery certification. The operator fault fixture proves client uncertainty and absence of automatic retry, not external acceptance. The release artifact proves exact source identity, not publication readiness. The independent Field identity/version registry proposal remains open; this work does not choose it.

Both the pre-skill baseline and these held-out tasks passed. Evidence supports runnable and portable instructions within the documented v1 prerequisites. It does not quantify improvement or establish human usability. No skill/content corrections were required by this evaluation.
