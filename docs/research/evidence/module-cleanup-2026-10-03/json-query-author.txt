- Core `query_eval.rs` facade and `normalization.rs`, `comparison.rs`, `read.rs` children.

`source.json` records owned source and lock hashes. `changes.patch`, `before/` and `source/` are the scoped review inputs.
Other cleanup agents' files and future stage 4.4 designs are excluded.

The public `rom::parse_json(&[u8]) -> rom::Result<rom::Value>` moves the existing duplicate-key visitor into core.
It accepts complete JSON roots, rejects nested duplicates and trailing input, and retains serde_json's recursion limit.
Errors remain `Error::invalid("request", "json")`, without input or parser diagnostics.
HTTP retains its object-only admission and typed schema error. CLI retains general root decoding and typed schema errors.
Caller byte limits are unchanged. Configuration's syntax-only visitor remains separate.

Query code moves into three named responsibilities: admission/normalization/anchors, predicate/key comparisons, and storage-read selection.
`query_eval.rs` contains module declarations and crate-private exports only.
The thirteen original function bodies compare equal after whitespace removal.
That source inspection aid is recorded in `task-a-query-body-comparison.json`; it is not a semantic test claim.
Imports and sibling method visibility changed only to support those modules.
Storage response validation, row/field authorization, filtering, anchors, sorting and limit order remain unchanged.
