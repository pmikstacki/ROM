# Maintained module audit

Inspection date: 2026-10-03. Worktree: `/root/ROM/.worktrees/release-query-index`.
Scope: maintained Rust sources and tests under `crates/`, plus `demo/src` and its current provider fixtures.
Historical prototypes, preserved worktrees and evidence are excluded from cleanup.
This is source inspection only. No refactor or test execution belongs to this audit.
The separate outage conformance addition has its own report and checks.

## Facade verdict

The explicit `lib.rs`/`mod.rs` rule is already satisfied in the audited maintained tree.
Eleven crate library roots and `demo/src/lib.rs` contain declarations, imports, exports and necessary definitions.
The only function bodies are the two delegating procedural-macro entry points in `rom-derive/src/lib.rs:8` and `:14`.
They are the documented exception; parsing and expansion remain in `expansion.rs` and its named children.
The only maintained `mod.rs` found is `rom-cli/tests/common/mod.rs`; it contains one declaration and reexport.

The current `demo/src/provider_profile.rs` facade is also thin, although its filename is not `lib.rs` or `mod.rs`.
Operator, channels, work ledger, native maintenance and backup already have cohesive named modules.
There is no remaining monolithic library root to split.
Source length alone is not a quality violation: the largest production files found are roughly 350–440 lines,
while the largest files are integration tests. Avoid splitting a coherent transaction solely to reduce line count.

## Concrete DRY gaps

### 1. Duplicate strict JSON decoding

`crates/rom-http/src/json.rs:4` and `crates/rom-cli/src/json.rs:4` contain the same `Unique` wrapper and recursive JSON visitor.
Both implementations reject duplicate keys, preserve nested arrays and convert the same primitive values.
The meaningful difference is the HTTP parser's top-level object check at `json.rs:60`.
CLI generic parsing allows other top-level values; operator-specific admission applies its own object checks.

This duplicates behavior that can drift during fixes, as the previous object-shape correction demonstrated.
A bounded cleanup can extract one strict Value decoder into an existing shared codec location.
Keep HTTP/CLI object admission, byte limits and safe error mapping at their current entry points.
Do not make one client's shape policy universal. Do not replace the visitor with ordinary Value parsing that accepts duplicate keys.
The shared location must preserve core's existing transport/driver dependency exclusions; no new parser framework is needed.

Affected checks: HTTP strict JSON/body tests, CLI JSON/input/failure/operator tests, nested-array negatives/positives,
feature-isolated core and packaged consumer checks. Public API selection for a cross-crate helper needs a small explicit design.

### 2. Repeated provider text validation

`demo/src/provider_profile/model.rs:43`, `secrets.rs:12` and `provisioning.rs:30` repeat the same
nonempty, byte-bound, trimmed and control-character checks with static `Denied` errors.
`command.rs:145` already calls the provisioning helper for decoded host text.

One private host-input validation helper can serve all four callers.
Keep secret-byte validation separate: credential bytes intentionally retain whitespace and use the 4,096-byte verifier bound.
Do not apply identifier normalization to secret material.
The helper should live with shared host inputs, rather than making standalone HostAuth depend on provisioning behavior.

Affected checks: provider host approval/reference negatives, configuration bounds, provisioning/maintenance negatives,
secret exact-byte tests, default-feature demo checks and feature-enabled Clippy.
Public `ApprovedProvider`, `SecretFiles`, `HostAuth`, `Provisioning` and `ProfileConfig` paths need no change.

These are source duplication findings. The audit found no new behavior defect in either case.
Do not edit the accepted stage 4.3 source before its integration gate.

## Preserve already shared mechanisms

- Core `StorageState`, work revision transitions and operator receipt validation already centralize semantics across SQLite and redb.
  Keep engine-specific transaction/open/recovery code separate; those operations have different guarantees.
- Worker and operator action reconciliation share the frozen receipt/action resolver. Do not duplicate it during reaction extraction.
- Delivery and verifier callbacks share supervision. Host authentication has a different blocking-worker lifetime contract;
  a generic executor abstraction is not justified merely because both use permits and timeouts.
- Provider file acquisition is already shared between secrets/configuration/maintenance inputs.
  Its Linux opened-handle checks must remain one implementation.
- Provider host/profile tests share the same Scratch, synthetic Provider and bounded subprocess helper.
  The recent sequence/retry fix must not be copied into another local fixture.
- JWT and introspection have different proof windows and transport/verification requirements.
  Do not merge their entire adapters as a line-count cleanup.
- Derived/manual Resources already pass the same registration and canonical codec contract.
  Keep generated bindings small; do not generate separate execution engines.

## Verification and integration constraints

Freeze each refactor's baseline and assign file ownership before edits.
Keep public import paths, serialized names, format versions, command fingerprints, replay versions and native obligations unchanged.
Use reexports for moved types and compile an external consumer; source path movement alone should not trigger a storage format change.
Do not combine behavior changes with structural extraction.

Run the affected existing tests and strict Clippy after each group.
After source review, run the full local verifier and package/downstream checks before integration, as AGENTS.md requires.
Preserve original failure logs and historical prototypes. Add current evidence instead of rewriting old records.

This audit identifies two concrete DRY gaps and five bounded cleanup groups.
It does not claim those groups are implemented or required to hold the accepted provider integration indefinitely.
