# ROM 0.0.2 SDK blob review

This independent review examined the new SDK binary methods and their shared request lifecycle. It used commit `e2f999d` with uncommitted SDK changes on 2026-10-04. The [source hashes](evidence/rom-0.0.2/sdk-blob-review/source.sha256), [original finite probes](evidence/rom-0.0.2/sdk-blob-review/probes-original.ts), and [probe output](evidence/rom-0.0.2/sdk-blob-review/probes.log) identify the reviewed slice. The reviewer changed no SDK or host source. The coordinator owns corrections.

## Findings

**P2 — An old capability response can become valid in a new session generation.** In `studio/src/lib/client/blobs.ts:112–122`, capability admission awaits the shared request, then stores the current generation. The request's generation check occurs earlier, in `studio/src/lib/client/session.ts:68`. A session invalidation between those steps gives the old capability response the new generation. The finite probe found this interleaving at microtask step 10. After invalidation, `reserveBlob` reached transport without a new capability request. Capture the original generation before the request. Compare it again before cache mutation and retain it in the cache. This is a stale client admission defect; it does not demonstrate bypass of the host's current identity or Resource checks.

**P2 — Dot-only IDs change the binary download route.** In `studio/src/lib/client/blobs.ts:185–188`, the ID occupies a URL path segment. `encodeURIComponent` leaves `.` and `..` unchanged. WHATWG URL normalization changes `attachment/.` into `attachment/` and `attachment/..` into its parent `blobs/`. Both IDs are valid nonempty Resource identifiers under the current native invocation contract. The probe confirmed both changed paths and accepted a successful binary response from them. Query encoding is a suitable transport route for these identifiers. Keep upload, reserve, detach and download correspondence tied to the submitted ID.

**P2 — Early response rejection does not cancel the owned body.** In `studio/src/lib/client/request.ts:19–24`, invalid or excessive `Content-Length` fails before reader ownership and its cleanup. The binary content-type check in `studio/src/lib/client/blobs.ts:194–198` also returns before body cleanup. The JSON content-type check has the same lifecycle in `studio/src/lib/client/request.ts:70–74`. The shared `run` finally block removes supervision but does not abort an otherwise live transport. The probe returned an open stream and recorded zero cancellations and an unaborted signal for both binary failures. Rejected bodies need finite best-effort cancellation; do not await an unbounded cancellation promise. This test establishes SDK ownership behavior. It does not measure a real browser socket leak.

**P2 — A superseded capability request can reopen admission after a failed refresh.** The generation correction alone does not order requests within one generation. Start an older capability request and pause its response. A newer request returns 403 and closes admission. Release the older valid response; it overwrites admission, and a subsequent reservation reaches transport. The [concurrent refresh probe](evidence/rom-0.0.2/sdk-blob-review/concurrent-refresh.ts) recorded [three transport calls in generation zero](evidence/rom-0.0.2/sdk-blob-review/concurrent-refresh.log). Fence cache writes with the latest request identity as well as generation. This result again concerns stale client admission; the final reservation was denied by the simulated host.

## Checked behavior and limits

The SDK keeps capability admission private. A returned capability object cannot widen its cloned cache. Upload limits use exact integer arithmetic for chunk capacity. Reservation inputs are copied through the strict wire codec before awaiting transport. Mutating a caller's input afterward cannot change the submitted ID or idempotency key.

Mutation replies check operation status and the admitted Resource kind and submitted ID. They require a non-null authorized projection. Download uses the admitted blob size and the configured response bound. It enforces binary content type and avoids JSON decoding. Redirects are rejected. Cookies use `same-origin`; mutations include the host CSRF token. No blob method manufactures an Actor or treats a provider receipt as projection authority.

The shared finite request deadline covers a transport that ignores AbortSignal. Session invalidation aborts currently tracked requests. Pre-aborted binary requests reach no transport. The new tests cover size admission, wrong reply identity/status, failed capability refresh, private cache cloning and input snapshots. The coordinator reported the full unit suite passing before this independent review; this review did not rerun that suite.

The probes used Node 22.16.0, WHATWG URL parsing and owned Web Streams. They ran no native core, browser, provider or network service. The capability probe uses a finite 40-step microtask sweep. These results are reproducible client conformance evidence. They do not establish actual browser authentication or human usability.

The API base and injected fetch function remain trusted host configuration. `credentials: same-origin` prevents cross-origin cookie use; it does not make an arbitrary configured base trustworthy. The host's current session, User, Provider and Link checks remain the authorization boundary. Cancellation of browser waiting does not imply cancellation of a supervised server upload or proof that a mutation did not commit. Callers need an explicit current projection or stable recovery procedure before declaring success or resubmitting a changed reservation.

## Correction review: 2026-10-04 00:32:32 UTC

The coordinator corrected all four findings. An independent [corrected invariant probe](evidence/rom-0.0.2/sdk-blob-review/probes.ts) passed against the [corrected source hashes](evidence/rom-0.0.2/sdk-blob-review/fixed-source.sha256). Its [output](evidence/rom-0.0.2/sdk-blob-review/fixed-probes.log) preserves both dot IDs in query parameters, records one cancellation per rejected binary body, and finds no stale generation window.

The independent [concurrent-refresh correction probe](evidence/rom-0.0.2/sdk-blob-review/concurrent-refresh-fixed.ts) also passed. Its [output](evidence/rom-0.0.2/sdk-blob-review/concurrent-refresh-fixed.log) records rejection of the superseded request, exactly two capability transports, and no reservation transport after the newer denial. No findings remain open in this scoped SDK review.

Actual host/browser attachment journeys remain a separate acceptance gate. Final artifact acceptance must build and serve the frozen final frontend, including the adopted attachment UI. This review is not a release approval.
