# ROM 0.0.2 Studio release design

Date: 2026-10-03. Status: selected release direction; implementation and acceptance remain incomplete.
The owner authorized autonomous design, implementation, verification, and release without further approval gates.

## Outcome

ROM 0.0.2 provides a working Studio connected to the maintained Rust framework.
Studio uses Svelte and selected shadcn-svelte components.
One Resource declaration supplies discovery, fields, action inputs, queries, mutations, and live observation.
Adding a Resource must not require another controller, repository, route, form, or subscription implementation.
Users and identity providers remain ordinary Resources. Authentication infrastructure establishes identity; Resource policies authorize access.

The release also closes selected integration gaps from the previous release.
It preserves existing mutation, query, ownership, lifecycle, and artifact guarantees.
Existing fixes are regression requirements, not defects to implement again.

Research inputs: [current frontend stack](../../research/rom-0.0.2-studio-stack-research.md), [browser authentication](../../research/rom-0.0.2-browser-auth-research.md), and [resilience gap audit](../../research/rom-0.0.2-resilience-gap-audit.md).
These reports establish documentation and source-review findings. Their proposed compatibility and browser trials have not yet run.

## Selected approach and alternatives

| Approach | Decision | Reason |
| --- | --- | --- |
| Svelte with Vite, static assets, optional Rust Studio host | Select for the first implementation trial | Keeps the application backend in Rust and permits persistent static deployment. |
| SvelteKit with a static adapter | Reserve | Useful if filesystem routing materially simplifies the selected screens. It adds framework compatibility work. |
| SvelteKit SSR and server actions | Reject for this scope | Duplicates server responsibilities and requires another deployment runtime. |

Selected shadcn-svelte source provides visual controls. Bits UI provides interaction primitives where those controls require them.
ROM owns the renderer registry and Resource semantics. A component library does not supply these contracts.
Record copied component provenance and review upstream changes separately from dependency updates.
Keep versions locked. Resolve versions after compatibility trials, not from a stale research report.

## Boundaries

The Rust core does not depend on Svelte, browser sessions, HTTP routes, or shadcn-svelte.
`rom-http` remains an optional generic transport binding.
`crates/rom-studio-host` composes the existing public runtime and transport with browser authentication and asset hosting.
`studio` contains static Svelte application assets, reusable components, the browser SDK, and browser tests.
The SDK uses the existing generic HTTP operations. Authentication endpoints belong to the optional host.
Browser data does not establish an Actor, administrative authority, or trusted provider endpoint.

The database remains the source of committed Resource state, receipts, events, and work.
Studio drafts and request tracking are temporary client state, never another persistence authority.
An accepted mutation remains supervised by ROM after its browser caller disconnects.
External blobs and delivery retain their existing guarantees and explicit reconciliation boundaries.

## Discovery and rendering

Extend authorized discovery with versioned action-input descriptions.
Keep action names compatible with existing clients. Add a separate action descriptor collection.
Inputs describe unit, scalar, and named-object shapes. Manual opaque inputs remain explicit and cannot fabricate a form schema.
Derived inputs and Field inputs provide descriptions from their actual codec bindings.
Registration checks metadata conformance. Discovery permission remains separate from permission to invoke an action.
Bound all descriptor output. Hidden Resource references and disallowed action metadata must not become visible through descriptions.

`ResourceBrowser`, `ResourceTable`, `ResourceForm`, `ActionForm`, and `QueryEditor` operate on accepted descriptors.
`FieldHost` selects a renderer by shape and explicit extension metadata, never by a switch on Resource kind.
Resource-owned field metadata may identify an optional versioned custom codec. This is not an independent Field registry.
Custom Field bindings supply that identity; the browser registry maps it to a reusable renderer through a public registration function.
Accept metadata only after descriptor/codec registration validation. Custom renderers never replace the authoritative Rust codec.
Use the same field controls in curated Users, Providers, Settings, and Work views.
Unsupported presentation must show a precise diagnostic. It must not silently discard a value.
No editor changes compiled Resource definitions or creates executable business handlers in the browser.

Field intent preserves omitted, null, value, and explicit removal where the operation supports them.
False, zero, and empty strings remain values. Integer encoding must preserve the entire i64/u64 domain.
Do not pass large integers through an ordinary JavaScript Number conversion.
Use bounded recursive editors for list/map shapes and an explicit custom-renderer registration route.
Rust codecs and policies remain authoritative even when the browser provides immediate validation.

## Browser authentication

Provide a ROM login screen and an explicit primary-provider redirect setting.
Use an actual tested OIDC authorization-code flow with PKCE for the human acceptance profile.
The host owns approved issuer/endpoints, callback origins, secret references, verification, and finite authentication admission.
Validate issuer, audience, signature, state, nonce, redirect binding, and one-time callback usage.
Use server-managed opaque sessions with HttpOnly cookies. Enable Secure cookies for deployed HTTPS and explicit loopback-only test exceptions.
Same-origin unsafe requests require CSRF protection and exact origin checks. Do not expose service client secrets or bootstrap authority to the browser.
Logout, expiry, revocation, User disablement, and provider changes invalidate current authority and clear browser projections.
Session expiry must not exceed verified identity expiry. Logout cancels all streams owned by that session, including other tabs.
Removing a cookie alone does not revoke an established stream. A host session guard must close it independently of Runtime authority checks.
An offline browser cannot erase disclosed data on a server signal. Clear projections on detected denial or session change, using bounded checks.
Prevent all subsequent server disclosure after revocation; document the finite detection bound for the browser.
No implicit email identity linking or unrestricted provider URL editing is permitted.
Keep approved provider selection and presentation settings in Resources without granting network acquisition authority through configuration alone.
The human verifier must produce the existing sealed verified-identity proof through a reviewed `rom-auth` OIDC adapter.
An external OAuth object or ID token is not an Actor. Bind the verified proof through the existing identity gate and captured provider revision.
The existing service-access-token verifier must not be reused as an ID-token verifier.

## Attachment execution

The optional host composes the existing `BlobService` with authenticated bounded upload and attachment routes.
The upload route does not bypass Blob Resource actions or claim atomicity between the database and external bytes.
Track accepted publication under BlobService supervision. Body cancellation and disconnect must preserve declared ownership and cleanup rules.
During shutdown, stop new host intake, close authentication admission and observers, then drain authentication and accepted blob work before Runtime shutdown.
Actual-process tests must establish that work is accepted and paused before sending the tested signal.

## Client lifecycle

Use fetch-based streaming for authenticated POST live queries. Native EventSource does not replace this wire contract.
Bound SSE frames, buffering, concurrent observations, and reconnect attempts.
Request generation guards prevent old queries and old sessions from replacing current results.
On gaps, reacquire a full authorized query result. Do not present a stale snapshot as complete current data.
Keep journal cursors distinct from query anchors. Moving pagination remains the selected semantics.

Each submitted mutation receives one operation identity retained while its outcome is unresolved.
An unknown outcome offers recovery using the exact original request. It must not create another idempotency key.
Conflicts preserve the draft and require reconciliation with current data.
Responses bind expected Resource kind, ID, revision, descriptor version, and relevant cursor/generation.
Logout removes data and subscriptions. Cached results never bypass current core authorization.

## Acceptance

Test the same Studio against SQLite and redb using actual HTTP, actual persistence, and a real local provider fixture.
Tasks and Inventory must share forms, tables, actions, filters, and live query machinery.
Add a held-out third Resource and one custom Field without editing generic components or adding a controller.
Exercise nullable and optional fields, nested structures, integer boundaries, aliases, and malformed responses.
Verify keyboard navigation, field labels, error focus, dialog focus restoration, and live row removal.
Automated accessibility checks supplement keyboard trials; neither proves universal accessibility.

Inject response loss after commit, authority changes, reconnects, overload, and descriptor changes with an open draft.
Interrupt accepted authentication and upload work through the actual serving process, then reopen and verify recovery.
Run an integrated provider-to-mutation-to-maintenance/reopen journey with the appropriate explicit identity re-establishment.
Do not describe separate component checks as that combined journey.
Add a policy that reads storage during an authorized query and a seeded operator obligation through native migration.

Release acceptance includes existing native gates, Studio type/unit/browser checks, extracted frontend assets, and extracted Rust consumers.
Artifacts bind the clean source, both lockfiles, frontend assets, dependency notices, fixed gate profile, and checksums.
Test large archives, missing assets, incorrect profiles, incomplete inventories, and duplicate publication attempts.
The persistent NixOS preview serves the same accepted assets and real API through the VPN HTTPS gateway.
Verify host restart, base path, direct navigation, asset MIME types, API proxying, and streaming.
Server-side probes do not prove that the owner's Mac has an active VPN route; record that distinction.

## Compatibility and limits

The owner selected the release identifier `0.0.2`. It numerically precedes `0.1.0-alpha.1`; this is deliberate release naming.
All maintained package versions and internal exact dependencies must agree. Preserve prior release artifacts unchanged.
Version numbering does not authorize downgrading the native storage marker or reinterpreting existing data.
Avoid a storage-format change unless the implementation requires one. If needed, provide explicit upgrade and recovery tests.
Retain the single-owner native profile, CLI, Tokio/Rayon execution, and adapter-independent core.
This release does not require WASM, RabbitMQ, shared tenancy, independent multiwriters, analytics, or a standalone Field registry.
Source APIs remain experimental. Process-exit recovery does not certify machine power-loss durability.
Browser trials establish tested workflows, not human productivity gains or universal OIDC/S3 compatibility.
