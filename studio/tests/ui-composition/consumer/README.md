# Installed maintenance workspace fixture

This independent application uses public ROM Studio package paths only.
Its host owns catalogs, labels, credentials, observation scope, pending intent storage and JSON export.
Workspace roles select the interface. Server policy determines access.

The technician selects equipment, opens responsive details, edits a UTC instant and exact reference, and saves an inspection.
History comes from the actual journal. Export captures a confirmed inspection and supports an explicit JSON download.
The dispatcher uses keyboard layout buttons. The Settings Resource stores the complete layout as a JsonDocument string.
Confirmed catalog positions and sizes determine the displayed grid panels. Hidden items remove their panels.
Catalog panels absent from Settings use full-width automatic flow. Narrow screens collapse to one column without changing Settings.

The host explicitly opens IndexedDB for principal-bound R4 intent slots.
After lost acknowledgement, reload offers explicit restore and exact invocation retry.
Inspection, WorkOrder and Settings recovery use the same public recovery controller.
WorkOrder recovery remains available when the confirmed completion disables a fresh completion action.
Confirmed completion clears its stored slot. Principal changes clear private disclosures and quarantine old callback results.

Open `/?workspace=public` for anonymous public-guide access without opening private IndexedDB storage.
The public host uses an explicit public observation scope and sends no Authorization header.
Select up to 20 guides, compute the exact BigInt sum of their bounded unsigned nominal values, and download captured JSON.
The export records selected confirmed revisions, dates and public fields through the public wire codec.
Selection or principal-context changes cancel retained results. Export rechecks authorized reads before bytes and current context before download.
The sum is a local arithmetic example. It is not an electrical installation recommendation.
The application owns the title predicate, guide catalog, selection bound, labels and export format.

From the repository root, prepare a frozen installed source candidate:

```sh
node studio/tests/ui-composition/verify.mjs NEW_OUTPUT --prepare-only
```

Run actual browsers against a coordinator-supplied immutable fixture binary:

```sh
ROM_WEBKIT_EXECUTABLE=/var/tmp/rom-studio-webkit-2359/pw_run.sh node studio/tests/ui-composition/verify.mjs NEW_OUTPUT --source-archive FROZEN_ARCHIVE --host-binary IMMUTABLE_BINARY --host-provenance IDENTITY_JSON --adapter sqlite --port 43301
```

Repeat with `--adapter redb`. Use a new output directory for each execution.
The verifier installs with `npm ci --install-links`, checks realized dependency versions and rejects source symlinks.
It compares the installed package with the supplied source archive before and after checks.
Each command has a 180-second timeout and an 8-MiB output bound. Browser execution uses one worker and both actual engines.

The loopback proxy forwards real backend work. It drops an acknowledgement only after an actual successful invocation response.
Held responses retain actual upstream bytes. Reset allocates another database path and preserves prior evidence.
Proxy traces, response bytes, readiness, controls and error logs have explicit bounds.
Each runtime verification reserves its own proxy port to test actual bind failure before the browser matrix.
The failed startup must drain its native child and permit the same database to reopen.

Fixed fixture credentials are not production authentication.
Native coverage applies to the immutable binary and source witness recorded in each result.
Historical recovery matrices use the earlier core. Public-guide matrices use the separately witnessed public-catalog binary.
Visibility coverage injects the document visibility adapter event; it does not test browser background timer throttling.
The public-catalog backend permits projected anonymous guide reads. Private resources, hidden-field queries and guest writes remain denied.
Account creation, invitations, optional account saving and production credential verification remain application-owned and unaccepted here.
Release artifacts, original-consumer adoption, held-out human review and assistive-technology acceptance remain separate gates.
The verifier rejects `--admit` until those gates have an independent admission workflow.
