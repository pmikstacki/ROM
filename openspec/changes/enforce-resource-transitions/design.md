# Design

`Definition<R>::validate_transition(fn(&Actor, Option<&R>, Option<&R>) -> Result<()>)` is an optional pure, deterministic, bounded callback. None means creation/deletion at either side, including absent prior state. The runtime normalizes the candidate, authorizes the actor and fields, and verifies the current revision. Before it creates the atomic commit bundle, it validates the actual current/candidate transition. The function runs on supervised blocking execution under the existing commit gate. It must not perform I/O, call the runtime, or create external effects. Panics become `Error::Panicked` without poisoning the commit gate.

The callback cannot grant authority. It sees only the already authorized Resource; current actor policy checks and CAS remain mandatory. Receipt lookup precedes validation, including the final lookup after proposal computation. Validation error creates no receipt, mutation, event, reaction or notification work. Default definitions pay only an option check. Only opted-in validators incur typed decoding.

Stock validates checked sum <= total and nonempty positive reservations; it rejects deletion while reservations exist. Checkout validates the enumerated outcome, immutable compensation context, and immutable confirmed terminal outcomes, including deletion. These are explicit demo business rules, not framework defaults. Valid targeted release and confirmed rejection remain ordinary actions.
