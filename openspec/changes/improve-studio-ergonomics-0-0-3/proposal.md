# Improve ROM Studio ergonomics for 0.0.3

## Why

The 0.0.2 browser workflows prove generic operation paths, but the owner found unreadable identities, missing custom editors, and protocol-shaped screens.
Studio must make backend operations understandable without introducing application-specific infrastructure.

## What Changes

- Improve Rust descriptor authoring and backend/frontend presentation conformance.
- Add human Resource titles, field labels, generic displays, and broader semantic controls.
- Use one right inspector for filters, Resource details, and Work inspection.
- Add Settings navigation from authorized Resource metadata, including plugin settings.
- Improve all screen states and test small browser ergonomics failures.
- Apply focused DRY/module refactors and add AI authoring guidance with verified boundaries.

## Impact

Resource semantics remain authoritative in the core. Presentation metadata does not grant authority or change persisted schema identity.
The initial implementation adds optional discovery presentation, a shared inspector, readable Work, and grouped Settings.
Semantic codecs, control expansion, full-screen acceptance, and the final 0.0.3 artifact remain separate delivery tasks.
Preserve 0.0.2 artifacts, source, historical prototypes, and test evidence.
