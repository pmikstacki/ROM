# Release ROM 0.1.0 for external applications

## Why

Astral Plane uses ROM in a deployed application, but its vendor patches and private Studio aliases expose public-interface gaps.
Existing conformance does not establish complete application restoration, production identity, upgrade, or bounded deployment behavior.
The owner requires these guarantees and reusable AI execution without changing the Resource model.

## What Changes

- Complete the 14 work packages in `docs/research/rom-0.1.0-consumer-research-plan.md`.
- Track all 30 consumer feedback groups with explicit dispositions and acceptance evidence.
- Add captured transition validation and supported public Studio controls and styles.
- Compose mutation recovery, projections, and durable flows through existing core contracts.
- Add optional provider-neutral AI execution and OpenRouter routing with bounded budgets and recovery.
- Establish one tested production deployment profile, restoration, upgrade, telemetry, and finite load limits.
- Produce matching clean-source Rust and Studio artifacts and publish the source and 0.1.0 tag.

## Impact

The core remains independent of database drivers, transports, model providers, and application domains.
Preserve public paths, authority checks, exact mutation identity, receipts, historical evidence, and retained artifacts.
GitHub remains source hosting. This scope does not enable Actions, publish to registries, or create a GitHub Release.
Research, proposed tests, and targeted passes do not complete this release.
